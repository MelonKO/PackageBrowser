# Процессные провайдеры

> Оригинальная серия: [[Package Browser]]

## Зачем

Не все менеджеры пакетов описываются одним `plugin.toml` в декларативном виде: чтение файлов базы менеджера (vcpkg), нестандартные форматы и обход медленного CLI требуют настоящей логики. Для таких случаев ядро запускает внешний процесс и общается с ним по JSON-RPC 2.0 через stdio.

Главное условие — **изоляция сбоев**: внешний процесс живёт в собственном `QProcess`, поэтому падение, зависание или «мусор» в stdout одного провайдера не затрагивают ни другие плагины, ни хост. Критерий этапа 3: *упавший провайдер не влияет на остальные окружения*.

## Как подключить процессный провайдер

Манифест плагина объявляет команду через секцию `[provider] exec` вместо `[tool]` и `[[locator]]`:

```toml
[plugin]
id = "builtin.vcpkg"
api = 1
name = "vcpkg"
ecosystem = "cpp"
capabilities = ["detect", "locate", "list"]

[provider]
exec = ["python", "vcpkg_provider.py"]
```

- `exec` — первый элемент это программа, остальные — фиксированные аргументы.
- Относительный путь, встречающийся в аргументах (например, `vcpkg_provider.py`), резолвится относительно каталога плагина — такой же принцип, как для самой программы. Это гарантирует, что скрипт найдётся независимо от рабочего каталога, с которым ядро запускает дочерний процесс.
- Манифест обязан объявить **ровно один** из `[provider]` или `[tool]`; иначе он отклоняется как невалидный.

Ядро запускает команду лениво (при первом запросе) через `ScanWorker`/`ProcessProvider` и распознаёт её через транспорт JSON-RPC.

## Транспорт

JSON-RPC 2.0 по stdio с рамкой `Content-Length` (как LSP):

```
Content-Length: 94\r\n
\r\n
{"jsonrpc":"2.0","id":7,"method":"list",...}
```

- **Запросы** — `{jsonrpc, id, method, params}`; ответ повторяет `id`.
- **Уведомления** (без `id`) — например, `progress`.
- **Отмена** — уведомление `$/cancel` с `params.id`.
- В `stdout` может быть только протокол; вся диагностика идёт в `stderr`.

Реализация в ядре: `src/rpc/ContentLengthFraming.{h,cpp}` (инкрементальный декодер, лимит размера полезной нагрузки) и `src/rpc/JsonRpcClient.{h,cpp}` (асинхронный клиент над `QProcess`, карта `id → callback`, таймауты, `stop()`).

## Контракт провайдера

Процессный провайдер отвечает на те же операции, что и декларативный (`docs/Плагины и JSON-RPC.md`, «Контракт провайдера»):

| Метод | Параметры | Результат |
| --- | --- | --- |
| `detect` | — | `tools: [{path, version}]` |
| `locate` | `tool` | `environments: [{root, scope, tool_id, inherits_from}]` |
| `locate_at` | `root` | `environments` (проектные, по маркерам) |
| `fingerprint` | `environment` | `fingerprint: string` |
| `list` | `environment, with_dependencies` | `installations: [{name, version, location}], complete` |

Ошибки — типизированные: JSON-RPC `error.data.kind` ∈ `ToolNotFound | EnvBroken | Timeout | ParseFailed | Untrusted | Unsupported`. Ядро отображает их в статус окружения (`EnvStatus`), а не в исключение.

## Жизненный цикл и карантин

Состояния — по `docs/Плагины и JSON-RPC.md` («Жизненный цикл плагина»): `Ready → Failed → Quarantined`.

- Ленивый старт: процесс запускается при первом запросе.
- На каждый запрос — дедлайн (15 с) и лимит размера вывода (8 МБ); зависший процесс убивается.
- Последовательные сбои (падение, таймаут, мусор в stdout, ошибка RPC) накапливаются; после порога `kQuarantineThreshold = 3` провайдер уходит в `Quarantined` и больше не опрашивается до ручного `reenable()`.
- Один успешный запрос сбрасывает счётчик.

## Изоляция сбоев и потоки

Скан выполняется на **рабочем потоке** (`src/catalog/ScanWorker.{h,cpp}`): он владеет `Cache`, `PluginHost` и `Scanner`, то есть и провайдеры (их `QProcess`), и SQLite-соединение создаются и живут на потоке рабочего. Интерфейс получает готовый снапшот данных через кешированные сигналы и никогда не трогает ядро кросс-поточно.

Падение одного провайдера приводит только к `EnvStatus::Error` (или `Untrusted` для недоверенного проекта) у **его** окружений; остальные окружения листируются как обычно. Проверяется тестом `pb_catalog_tests::failingProcessProviderDoesNotBreakOtherEnvironments`.

## Реализация

- `src/provider/ProcessProvider.{h,cpp}` — адаптер `IProvider` над `JsonRpcClient`; асинхронность сворачивается в блокирующий вызов (вложенный цикл событий) под синхронный контракт ядра. Это осознанный компромисс MVP: полноценный неблокирующий движок — отдельная задача.
- `src/plugin/PluginHost` — умеет создавать `ProcessProvider` для манифестов с `[provider]`.
- `src/plugin/PluginManifest.{h,cpp}` — парсинг и валидация секции `[provider]`.
- `app/ui/PluginListModel.{h,cpp}` — экран плагинов (состояние, переключатель «включён» через `AppSettings.disabledPluginIds`).
