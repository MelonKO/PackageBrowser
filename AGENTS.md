# AGENTS.md

Инструкции для агентов, работающих с этим репозиторием.

## Проект

Desktop-приложение на **C++/Qt 6 (Widgets)**: просмотр пакетов разных менеджеров (pip, npm, vcpkg) с ответом на вопрос «из какого окружения пакет». Архитектура описана в [docs/](docs/) (в особенности `docs/Package Browser.md` и `docs/Доменная модель.md`).

Стек: CMake, C++17, Qt 6 Widgets, SQLite (Qt SQL). Официальная политика сборки — CMake. Зависимости через Conan (см. docs).

## Правило gitflow (обязательно)

Репозиторий ведётся по правилам **git-flow** (аддон не используется — ветки создаются и ведут вручную):

- **`main`** — стабильная ветка. Здесь только релизы. Коммиты напрямую в `main` запрещены.
- **`develop`** — интеграционная ветка разработки. Сюда мержатся завершённые фичи.
- **`feature/<имя>`** — ветки новой функциональности. Создаются **только от `develop`**, вливаются обратно в `develop` (`--no-ff`).
- **`release/<версия>`** — подготовка релиза: создаётся от `develop`, вливается и в `main`, и в `develop`.
- **`hotfix/<имя>`** — срочные исправления: создаются от `main`, вливаются и в `main`, и в `develop`.

Обязательные правила для агента:

1. **Никогда** не коммитить и не делать изменения напрямую в `main`.
2. Для любой задачи (новая функциональность, правка) создавать ветку `feature/<имя>` от актуального `develop`.
3. `develop` и `main` менять только через merge готовых веток, релизные коммиты и hotfix.
4. Перед началом работы над новой фичей: `git switch develop`, `git pull --ff-only` (если не ошибаетесь в актуальности), затем `git switch -c feature/<имя>`.
5. При завершении merge в `develop` — только `--no-ff`.
6. Своей ветки `feature/<имя>` не указывать в AGENTS.md — она одна, создаётся и удаляется в процессе работы.

## Сборка

```sh
# зависимости Qt через Conan (см. docs)
cmake -S . -B build
cmake --build build
ctest --test-dir build
```

## Тесты

Инфраструктура: Qt Test (`Qt6::Test`). Запуск: `ctest --test-dir build`. Отключить тесты: `-DPACKAGE_BROWSER_BUILD_TESTS=OFF`.
